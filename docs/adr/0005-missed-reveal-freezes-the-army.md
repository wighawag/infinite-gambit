# A missed reveal freezes the army forever

An army whose commitment is never revealed never moves again, its king can no longer exit, and it can still be captured; in the framework's terms this is the forfeit, and its stake stays on the board as prey. Reveals land during the reveal phase in whatever order, so a late revealer has already seen everyone else's moves, and staying silent when they look bad is an option worth up to a queen or a king. We rejected freezing for one cycle (it costs about as much as a pass), a token bond (it has to be sized against that option), and losing the moved piece (the chain cannot know which piece a commitment held without the reveal). The cost of an honest miss (a crash, a gas spike) is accepted. The client mitigates it with the local revealer and a deadline warning. If playtests show it is too harsh, the fallback is a freeze lasting N cycles.

A deployment that is committed and never revealed has no army to freeze yet, so its locked stake is burned instead (a real ERC20 burn that reduces the supply, not tokens left sitting in the contract). A refund would make "commit a deployment, watch the cycle's reveals, cancel" free.

**What "frozen" means on chain.** The base only runs `_forfeit` when somebody settles the missed reveal, so an army counts as frozen when its frozen flag is set OR it holds an unrevealed commitment from a past cycle. Every check that cares (moving, exiting, the HUD, a table's waited-for set) uses that definition.
