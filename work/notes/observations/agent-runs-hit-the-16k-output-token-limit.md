---
title: 'Build agents on hard contract tasks die on the 16,384-token output limit'
---

Observed 2026-11-05/06 by the drive-tasks conductor over the `infinite-chess` drive. Four `dorfl do` runs failed with `agent failed: ... Response was truncated: the model reached its output token limit` (`chess-moves` once, `chess-king-capture-merge` twice, `chess-capture-loops` once). The pi session of one of them (`~/.pi/agent/sessions/--home-wighawag-.dorfl-work-github-com__wighawag__chess-battleground__chess-king-capture-merge--/`) shows the cause: a single assistant reply spent all 16,384 output tokens on reasoning (`stopReason: length`, `reasoning: 16384`) although the session's thinking level is `off`, about 25 minutes in. The run then ends with nothing saved unless the agent had already written files (one of the four saved a wip commit). Every retry with a "work in small steps" handoff succeeded, so it is recoverable, but each failure costs about half an hour.

The `MCP: Failed to connect to miro: OAuth authentication required` line in the same reason is noise from the harness's MCP config, not the failure.

Possible levers (none applied): a higher max output tokens for the build model (`etherplay/claude-opus-5-5` under pi), a different model for `dorfl` builds, or a per-repo `promptGuidance` nudge to act before planning the whole task.

Recurred 2026-11-06 on `lean-rules-captures-without-merges-and-stones`, twice in a row, and this time the "work in small steps" handoff did NOT rescue it. Both pi sessions (`~/.pi/agent/sessions/--home-wighawag-.dorfl-work-github-com__wighawag__chess-battleground__lean-rules-captures-without-merges-and-stones--/`) show the same shape: 7 to 9 short tool-call replies reading files (under 600 output tokens each), then one reply with `stopReason: length`, 16,384 output tokens and an empty visible thinking block, so the whole budget went to hidden reasoning before the agent wrote a single file. Nothing was saved either time. The task's own prompt and the appended handoff both already said to act before planning, so prompt guidance alone is not a sufficient lever for a task this size: the build model's max output tokens (or the model) is. Separately, `git push` now reports `This repository moved. Please use the new location: git@github.com:wighawag/infinite-gambit.git`; the redirect still works.

Resolved 2026-11-06: the limit came from pi's default `maxTokens` (16384), which applies because `etherplay/claude-opus-5-5` sets none in `models.json`. That file is a sops template rendered by Nix from `my-boxes/hosts/telemaque/home/.pi/agent/models.json`. Setting `"maxTokens": 64000` there (branch `pi-opus-max-tokens` of my-boxes, cut from the converged `67367c1`, then converged) fixed it. The third run of `lean-rules-captures-without-merges-and-stones` had a 20,664-token reply and finished, and the other three lean-rules tasks built without hitting the limit. pi's own catalog lists 128000 for this model if 64000 is ever too low. The other `etherplay/*` models in that file still have no `maxTokens`.
